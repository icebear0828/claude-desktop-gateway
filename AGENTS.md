# Repository Guidelines

## Project Structure & Module Organization

This package is moving from a TypeScript reference gateway to a Go core with a future Wails desktop configuration console. Both expose Anthropic-compatible endpoints and forward requests to OpenRouter first.

- `cmd/gateway/` starts the Go gateway MVP.
- `internal/config/` loads environment variables and resolves model routes.
- `internal/gateway/` owns `/health`, `/v1/models`, and `/v1/messages`.
- `src/index.ts` starts the TypeScript reference server.
- `src/app.ts` builds the Hono reference app and HTTP routes.
- `src/config.ts` loads environment variables and model aliases.
- `src/translation.ts`, `src/stream.ts`, and `src/types.ts` hold request/response conversion, streaming conversion, and shared types.
- `tests/*.test.ts` contains Vitest tests. `tests/real-openrouter.test.ts` is the live upstream test.
- `dist/` is generated by TypeScript; do not edit it by hand.

## Build, Test, and Development Commands

Run commands from this directory:

- `npm install` installs dependencies from `package-lock.json`.
- `npm run dev` runs `src/index.ts` with `tsx` for local development.
- `npm run build` compiles TypeScript to `dist/`.
- `npm start` runs the compiled server from `dist/index.js`.
- `npm test` runs the mocked Vitest suite.
- `npm run test:real` runs the OpenRouter integration test; it requires `OPENROUTER_API_KEY`.
- `GOCACHE=/private/tmp/go-build-cache go test ./...` runs Go core tests.
- `go run ./cmd/gateway` starts the Go gateway core.
- `CLAUDE_GATEWAY_CONFIG=gateway.local.json go run ./cmd/gateway` starts the Go core from an ignored local config file.
- `CLAUDE_GATEWAY_CONFIG=gateway.lan.json go run ./cmd/gateway` binds according to LAN config; non-loopback hosts require `CLAUDE_GATEWAY_API_KEY`.

Default local URL is `http://127.0.0.1:8787`.

## Coding Style & Naming Conventions

Use TypeScript ES modules with explicit types at public boundaries. Avoid `any`; prefer concrete types, generics, or `unknown` with narrowing. For Go, keep packages small, run `gofmt`, and keep provider-specific behavior out of HTTP handlers.

## Testing Guidelines

Tests use Vitest for the TypeScript reference and Go `testing`/`httptest` for the new core. Add or update tests before changing behavior. Changes involving OpenRouter, SDK/API behavior, streaming, or protocol translation require a real 3-call OpenRouter test before being marked complete.

## Commit & Pull Request Guidelines

This checkout has no local `.git` history, so use Conventional Commit-style messages: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, or `chore:`. Keep commits focused and describe why behavior changed when it is not obvious.

PRs should include a concise summary, test results (`npm test`, `npm run build`, and `npm run test:real` when applicable), linked issues if any, and notes for environment or model-alias changes. Never include real API keys in commits, logs, screenshots, or PR text.

## Security & Configuration Tips

Required and optional environment variables are documented in `README.md`. Keep `OPENROUTER_API_KEY` and `CLAUDE_GATEWAY_API_KEY` in env or a system keychain, never in JSON config. JSON may reference secrets only via `apiKeyEnv` or `gatewayApiKeyEnv`. Any LAN/VPS binding must require a gateway API key.
